# BA Macro 0.2.66 추가 성능 점검

2026-10-13, main의 0.2.65를 기준으로 측정했다. 실제 사용자 파일 대신 임시 디렉터리와 합성 프로필을 사용했다.

## 확인된 병목과 수정

외부 프로필의 최근 복사본 동기화에서 같은 복사본을 여러 번 읽고, 변경이 없는 경우에도 원본과 복사본의 JSON을 모두 해석했다. 심각도는 낮음(큰 파일의 설정 저장 대기), 수정 위험도는 낮음(입력·UI와 분리된 저장 모듈의 검증 바이트 재사용)으로 분류했다.

- 복사본을 한 번 읽고 기존 SHA-256 지문과 비교한다.
- 외부 원본과 검증된 복사본의 바이트가 같으면 JSON 해석과 재저장 없이 반환한다.
- 서식만 다르거나 저장용 프로필 객체를 받은 경우 검증한 복사본 바이트를 재사용해 내용을 비교한다.
- 내용이 같은 복사본은 다시 읽어 해시를 계산하지 않는다.
- 변경된 내용은 기존 원자적 JSON 저장을 사용한다. 외부에서 수정·손상시킨 복사본은 별도 파일로 보존하며 새 복사본을 만든다.

## 측정

프로필: 200행, 행마다 `click 100,200` 7,000줄, 저장 파일 21,036,504바이트. 같은 Python 환경에서 커밋 전후 저장 모듈을 각각 로드해 측정했다. 디스크 캐시·PC 상태에 따라 실제 시간은 달라진다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 변경 없는 외부 프로필 동기화, 7회 중앙값 | 106.37ms | 15.61ms |
| 위 작업의 tracemalloc 최대 메모리 | 79.0MiB | 40.1MiB |
| 내용이 변경된 외부 프로필 저장의 최대 메모리 | 60.3MiB | 59.0MiB |

일반 UI 연속 편집 40회의 호출 시간 중앙값은 수정 전 약 2.3ms였다. 해당 경로는 병목으로 판단하지 않고 변경하지 않았다. 위 개선율은 전체 앱 속도가 아닌 외부 프로필 동기화 작업에 한정된다.

## 검증과 종료 범위

- 저장 관련 테스트 30개 통과. 새 테스트 3개는 동일 파일의 1회 읽기·불필요한 해석/쓰기 제거, BOM·JSON 서식 차이 보존, 저장 스냅샷 비교 시 바이트 재사용을 확인한다.
- 기존 테스트로 외부 수정·손상 복사본 보존, 저장 실패 재시도, 자동저장 순서 및 설정 보호를 확인했다.
- 전체 자동 테스트 557개 통과(18.208초), git diff --check 통과.
- macro.json / setting.json SHA-256 변경 없음. UI·입력 동작·기본값·프로필 형식 변경 없음.

확인된 병목 수정 후 추가 탐색은 종료했다. 남은 후보는 실제 게임에서 장시간 실행·포커스 전환·최소화 시 동작 검증이다. 이번 작업에서는 실제 게임 입력을 수행하지 않았다.
